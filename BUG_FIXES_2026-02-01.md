## Bug #1: Incorrect JQL Filter in Jira Trigger ⚠️ CRITICAL

### Details

**Workflow**: SF Agent 1 - Initial Analysis (ID: 2A6XqlHc9b48hjd6)
**Node**: "Jira Trigger - New SF Story"
**Severity**: Critical - Workflow never triggers

### Problem

The JQL filter was configured to look for **Incident** type issues:

```jql
type = Incident AND labels = "salesforce"
```

However, the test ticket and all user stories are **Story** type, not Incident type. This meant:
- ❌ Workflow 1 would never trigger for any Story
- ❌ Test ticket would be ignored
- ❌ Agent would appear to be "not working"

### Root Cause

The node was created with an incorrect issue type filter during initial workflow setup.

### Fix Applied

Changed JQL filter to:

```jql
type = Story AND labels = "salesforce"
```

### Verification

To verify the fix:
1. Go to n8n → Workflows → SF Agent 1 - Initial Analysis
2. Click "Jira Trigger - New SF Story" node
3. Check "JQL Filter" field shows: `type = Story AND labels = "salesforce"`

### Impact

**Before**: Workflow never triggers for Stories
**After**: Workflow triggers correctly when a Story with label "salesforce" is created

## Bug #2: Missing HTTP Request to Trigger Workflow 3 ⚠️ CRITICAL

### Details

**Workflow**: SF Agent 1 - Initial Analysis (ID: 2A6XqlHc9b48hjd6)
**Missing Node**: HTTP Request to call Workflow 3
**Severity**: Critical - Execution stops prematurely

### Problem

When the agent determines no questions are needed:
1. ✅ Posts "Ready to execute" comment
2. ✅ Adds `sf-agent-ready-to-execute` label
3. ❌ **Nothing happens next** - workflow ends

The workflow was missing an HTTP Request node to actually trigger Workflow 3.

### Expected Behavior

```
Parse AI Response
  ↓
Has Questions? (IF)
  ↓ (false - no questions)
Jira - Ready to Execute Comment
  ↓
Jira - Add Ready Label
  ↓
❌ MISSING: Trigger Workflow 3 ❌
```

### Fix Applied

Added new node: **"Trigger Workflow 3"**
- **Type**: HTTP Request
- **Method**: POST
- **URL**: `https://<your-n8n-instance>.app.n8n.cloud/webhook/sf-agent-execute`
- **Body**: JSON with issue key, summary, description
- **Position**: After "Jira - Add Ready Label" node

**Node Configuration**:
```json
{
  "id": "http-trigger-workflow3-1",
  "name": "Trigger Workflow 3",
  "type": "n8n-nodes-base.httpRequest",
  "parameters": {
    "method": "POST",
    "url": "https://<your-n8n-instance>.app.n8n.cloud/webhook/sf-agent-execute",
    "sendBody": true,
    "specifyBody": "json",
    "jsonBody": "={{ JSON.stringify({ issueKey: $json.issueKey, summary: $json.summary, description: $json.description }) }}"
  }
}
```

**Connection Added**:
```
Jira - Add Ready Label → Trigger Workflow 3
```

### Verification

To verify the fix:
1. Go to n8n → Workflows → SF Agent 1 - Initial Analysis
2. You should see a new node "Trigger Workflow 3" after "Jira - Add Ready Label"
3. Check the node is connected (line from "Jira - Add Ready Label" to "Trigger Workflow 3")

### Impact

**Before**: Agent adds label but never executes configuration
**After**: Agent automatically triggers Workflow 3 to deploy to Salesforce

## Bug #4: Incorrect Webhook Data Access in Extract Issue Details ⚠️ CRITICAL

### Details

**Workflow**: SF Agent 1 - Initial Analysis (ID: 2A6XqlHc9b48hjd6)
**Node**: "Extract Issue Details"
**Severity**: Critical - Workflow crashes on execution

### Problem

The code was trying to access issue fields directly from the webhook payload:

```javascript
const issue = $input.first().json;
issue.fields.summary  // ❌ Throws error: Cannot read properties of undefined
```

But Jira Trigger sends webhook data with the issue nested under an `issue` key:

```json
{
  "webhookEvent": "jira:issue_created",
  "issue": {              // ← Issue is nested here!
    "key": "PROJ-123",
    "fields": { "summary": "..." }
  }
}
```

**Error Message**:
```
Cannot read properties of undefined (reading 'summary') [line 7]
```

### Root Cause

The code assumed the Jira Trigger would send issue data directly at the root level, but Jira webhooks wrap the issue in an outer object with metadata.

### Fix Applied

Updated code to extract issue from webhook structure:

```javascript
// Extract key details from Jira issue
// Jira Trigger sends webhook data with issue nested under 'issue' key
const webhookData = $input.first().json;
const issue = webhookData.issue || webhookData; // Handle both webhook and direct formats

// Verify we have the issue data
if (!issue || !issue.fields) {
  throw new Error('Invalid Jira webhook data structure. Missing issue or issue.fields.');
}

return [{
  json: {
    issueKey: issue.key,
    summary: issue.fields.summary,
    description: issue.fields.description || 'No description provided',
    project: issue.fields.project.key,
    issueType: issue.fields.issuetype.name,
    assignee: issue.fields.assignee?.displayName || 'Unassigned',
    reporter: issue.fields.reporter?.displayName || 'Unknown',
    created: issue.fields.created,
    labels: issue.fields.labels || []
  }
}];
```

### Key Changes

1. **Renamed variable**: `issue` → `webhookData` (clearer intent)
2. **Extract issue**: `const issue = webhookData.issue || webhookData;`
   - First tries to get `webhookData.issue` (webhook format)
   - Falls back to `webhookData` (direct format, for manual testing)
3. **Added validation**: Checks if `issue` and `issue.fields` exist
4. **Added labels**: Extracts `labels` array for label management
5. **Error handling**: Throws descriptive error if data structure is invalid

### Verification

1. Open Workflow 1 → "Extract Issue Details" node
2. Verify code starts with: `const webhookData = $input.first().json;`
3. Verify next line: `const issue = webhookData.issue || webhookData;`

### Impact

**Before**: All executions failed with undefined error at "Extract Issue Details"
**After**: Successfully extracts issue data from webhook and passes to next nodes

## Bug #5: Invalid JSON Expression in Claude HTTP Request ⚠️ CRITICAL

### Details

**Workflow**: SF Agent 1 - Initial Analysis (ID: 2A6XqlHc9b48hjd6)
**Node**: "Claude - Analyze Requirement"
**Severity**: Critical - API call fails

### Problem

The HTTP Request node's JSON body was using incorrect expression syntax:

```javascript
jsonBody: "={
  \"content\": \"...{{ $json.summary }}...\"  // ❌ Wrong!
}"
```

**Issues**:
1. Using `{{ }}` template syntax inside JSON body
2. n8n couldn't parse the JSON properly
3. Resulted in error: "JSON parameter needs to be valid JSON"

**Error Message**:
```
JSON parameter needs to be valid JSON
```

### Root Cause

Mixed up template literal syntax `{{ }}` (for parameter fields) with expression syntax `={{ }}` (for JSON bodies). Inside expressions, variables should be accessed directly using `$json.field`.

### Fix Applied

Updated JSON body to use proper n8n expression syntax with string concatenation:

```javascript
jsonBody: "={{ {
  \"model\": \"claude-sonnet-4-20250514\",
  \"max_tokens\": 4000,
  \"temperature\": 0.2,
  \"messages\": [
    {
      \"role\": \"user\",
      \"content\": \"You are an expert Salesforce developer agent...\" +
                  $json.summary + \"\\n...\" +
                  $json.description + \"\\n...\" +
                  $json.issueType + \"\\n...\" +
                  $json.project + \"...\"
    }
  ]
} }}"
```

**Key Changes**:
1. **Expression wrapper**: `={{ { ... } }}` - Returns JavaScript object
2. **String concatenation**: Uses `+` operator for dynamic values
3. **Direct variable access**: `$json.summary` (not `{{ $json.summary }}`)
4. **Valid JSON**: Results in properly formatted JSON for Anthropic API

### Verification

1. Open Workflow 1 → "Claude - Analyze Requirement" node
2. Check "JSON Body" field starts with: `={{ {`
3. Verify uses `+` for concatenation, not `{{ }}`

### Impact

**Before**: HTTP Request failed with JSON parsing error, Claude AI never called
**After**: Valid JSON sent to Anthropic API, AI analysis succeeds

## Bug #6: Incorrect Issue Key Reference in Jira Label Nodes ⚠️ CRITICAL

### Details

**Workflow**: SF Agent 1 - Initial Analysis (ID: 2A6XqlHc9b48hjd6)
**Nodes**:
- "Jira - Add Awaiting Label"
- "Jira - Add Ready Label"
**Severity**: Critical - Jira updates fail

### Problem

The Jira update nodes were trying to get the issue key from the wrong data source:

```javascript
issueKey: "={{ $json.issueKey }}"  // ❌ Wrong!
```

**Flow context**:
```
Parse AI Response (has issueKey)
  ↓
Has Questions? (IF)
  ↓
Jira - Post Questions (returns comment data, NO issueKey)
  ↓
Jira - Add Awaiting Label (tries $json.issueKey from comment ❌)
```

**Error Message**:
```
404 - The resource you are requesting could not be found
Issue does not exist or you do not have permission to see it.
```

### Root Cause

After "Jira - Post Questions" node, `$json` contains comment data (not issue data). The comment object doesn't have an `issueKey` field, so the expression evaluated to `undefined`, causing a 404 error.

### Fix Applied

Updated both nodes to reference the correct node for issue key:

**"Jira - Add Awaiting Label"**:
```javascript
issueKey: "={{ $('Parse AI Response').item.json.issueKey }}"
labels: "={{ ['salesforce', 'sf-agent-awaiting-response'] }}"
```

**"Jira - Add Ready Label"**:
```javascript
issueKey: "={{ $('Parse AI Response').item.json.issueKey }}"
labels: "={{ ['salesforce', 'sf-agent-ready-to-execute'] }}"
```

**Key Changes**:
1. **Explicit node reference**: `$('Parse AI Response').item.json.issueKey`
2. **Simplified labels**: Direct array instead of concatenation logic

### Verification

1. Open Workflow 1 → "Jira - Add Awaiting Label" node
2. Check Issue Key field uses: `$('Parse AI Response').item.json.issueKey`
3. Repeat for "Jira - Add Ready Label" node

### Impact

**Before**: 404 error, labels never added, state tracking broken, Workflow 2 never triggers
**After**: Labels successfully added, workflow state tracking works, Workflow 2 can detect labeled issues

## Bug #7: Workflow 3 Not Triggering - Data Format Mismatch ⚠️ CRITICAL

### Details

**Workflow**: SF Agent 1 - Initial Analysis (ID: 2A6XqlHc9b48hjd6)
**Node**: "Trigger Workflow 3" (HTTP Request)
**Severity**: Critical - Workflow 3 never executes autonomously
**Discovery**: User reported "Workflow3 is not getting executed autonomously"

### Problem

Data format mismatch between how Workflow 1 sends data and how Workflow 3 expects it.

**Workflow 1 sent**:
```javascript
{ issueKey: "KAN-9", summary: "...", description: "..." }
```

**Workflow 3 expected**:
```javascript
{ body: { issueKey: "KAN-9", summary: "...", description: "..." } }
```

**Result**: Workflow 3's "Jira - Get Issue" node tried to access `$json.body.issueKey` but got `undefined`.

### Root Cause

n8n webhooks often expect data nested under keys like `body`, `query`, or `headers`. Workflow 1 was sending data at root level, but Workflow 3 was accessing `$json.body.issueKey`.

### Fix Applied

Updated "Trigger Workflow 3" HTTP Request node:

**Before**:
```javascript
jsonBody: "={{ JSON.stringify({
  issueKey: $json.issueKey,
  summary: $json.summary,
  description: $json.description
}) }}"
```

**After**:
```javascript
jsonBody: "={{ JSON.stringify({
  body: {
    issueKey: $json.issueKey,
    summary: $json.summary,
    description: $json.description
  }
}) }}"
```

### Impact

**Before**: Workflow 3 never triggered, agent appeared to stop after adding "ready-to-execute" label
**After**: Workflow 3 triggers correctly and proceeds to deployment

**Reference**: See [BUG_FIX_WORKFLOW3_TRIGGER.md](BUG_FIX_WORKFLOW3_TRIGGER.md) for complete details

- **Node**: "Claude - Re-analyze with Answers"
- **Error**: Using `{{ }}` template syntax inside JSON body
- **Impact**: "JSON parameter needs to be valid JSON" error

- **Node**: "HTTP - Trigger Workflow 3"

**Fix 1: Variable Name**


**Fix 2: Claude JSON Expression**
```javascript
// Before:
jsonBody: "={ \"content\": \"...{{ $json.summary }}...\" }"

  \"messages\": [{
    \"content\": \"text \" + $json.summary + \" more\"
```

```javascript
// Before:
```
